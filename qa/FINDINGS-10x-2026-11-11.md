## DEFECTS

### P1 — CRITICAL: 20/20 inner pages crash client-side (white "Application error" screen)
- **Pages:** emergency-water-extraction, basement-flooding-cleanup, window-well-flooding, burst-pipe-water-damage, sewage-backup-cleanup, water-heater-leak-cleanup, swamp-cooler-leak-water-damage, ceiling-water-damage, crawl-space-water-damage, hardwood-floor-cabinet-drying, condo-apartment-water-damage, commercial-water-damage, storm-flood-damage, mold-remediation, water-leak-detection, water-damage-repair, midvale-water-sewer-emergency-contacts, locations/cottonwood-heights-ut, locations/south-salt-lake-ut, locations/magna-ut — every inner page, desktop + mobile.
- **What the visitor sees:** white page, one centred line: *"Application error: a client-side exception has occurred (see the browser console for more information)."* No header, hero, H1, buttons, body, or footer. Browser measurement: h1=0, title="", btn1=null on all 20 (desktop + 390 + 320).
- **Visual proof:** 40/42 top screenshots are the error screen (2 reviewers, independent). All 20 desktop error shots byte-identical (sha256 `e34560350736fecf0863a4b25eb66429d72867c9293ba98fae4f4f34004c2f26`); all 20 mobile error shots byte-identical (sha256 `86b2aefdbf2195b9386b915217516d7ccf9f8792c7a6146ed44a96604d83f442`). All 20 desktop-full shots byte-identical (12,287 bytes each).
- **Console:** `ChunkLoadError: Loading chunk 42 failed` + Minified React error #423.
- **Root cause (verified live via curl):** `next.config.mjs` has NO `assetPrefix`/`basePath` (only `output: "export"`, `trailingSlash: false`, `images.unoptimized`), so the webpack runtime's public path is `/`. The `<script src>` tags in the live HTML ARE prefixed (by `publish_prefix.py`) so initial chunks load, but hydration's dynamic chunk ensure uses the unprefixed runtime path → 404 → error boundary unmounts the whole page. Proof: prefixed chunk `https://growthaura.github.io/midvale-water-damage/_next/static/chunks/app/%5Bslug%5D/page-5ab7919444d9be38.js` = **200**; unprefixed `https://growthaura.github.io/_next/static/...` = **404** (same for chunk 258 and the locations chunk `app/locations/%5Bslug%5D/page-9135108…`).
- **Homepage works** (h1=1, no pageerror) — its page chunk does not trigger the failing dynamic load. The homepage ALSO requests unprefixed chunks in the console (404s, e.g. `/_next/static/chunks/390-…`, `app/page-…`) but tolerates them without a pageerror.
- **Why the 2026-11-10 round missed it:** its "live" render was of the local `out/` served at ROOT, where `/_next/...` resolves fine; the subpath chunk path was never exercised.
- **Impact:** with JS enabled (including Googlebot rendering), 20/21 live pages show only the error line. The SSR HTML is still served (curl shows H1=1 and full content present in the HTML), so this is a hydration/client-side failure, not missing content.
- **Fix direction (for the builder, NOT this test task):** set `assetPrefix` (or `basePath`) to `/midvale-water-damage/` at build time, re-export, re-push, then re-run this QA fresh.
